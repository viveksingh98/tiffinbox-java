# c2-unit26 — NIO.2 Deep-Dive: walk, WatchService and Channels (JDK 25.0.4.1)
Run the four compact source files directly, **no flags**, from inside this folder: `java Walk.java` · `java Watch.java` · `java Channels.java` · `java Missing.java`.
`Walk.java` builds its own `menus/` tree, prints `entries under the root: 8` (**`walk` counts directories too**), finds the three CSVs with `Files.find`, sums them to `67`, reads `BasicFileAttributes` once, then deletes everything in `Comparator.reverseOrder()` and prints `cleaned up:            true` (5/5 byte-identical, md5 `d3eaa380…`). `Watch.java` registers `menus/` for `ENTRY_CREATE`/`ENTRY_DELETE`, a virtual thread adds and removes `week-3.csv`, and a `CountDownLatch(1)` — **not a `Thread.sleep`** — keeps it deterministic (5/5, md5 `26852ae1…`; ~4.4–5.6 s wall clock, because macOS gets `sun.nio.fs.PollingWatchService`, not `inotify`).
`Channels.java` shows `position · limit · capacity` across `allocate` → `read` → `flip`, decodes the 31 bytes and memory-maps the same file (5/5, md5 `45000296…`). It names its charset in **both** places it turns bytes into text — the mapped read used to build its string with `(char) map.get(i)`, a raw byte-to-char cast (which *is* Latin-1 decoding) and now calls `StandardCharsets.UTF_8.decode(map.slice(0, end))`; the output is byte-identical, because the fixture is ASCII, which is exactly why that bug survives in real code. `Missing.java` **fails on purpose**: `NoSuchFileException: menus/week-9.csv` from line 8, exit code **1** (5/5, md5 `779b1d64…`). Its `Path.of("menus")` is **relative to the directory you run from** — run it here, where there is no `menus/`, which is what its own first printed line (`does menus/ exist? false`) checks for you. The full trace is **eleven** `at` frames; the slide shows three and marks `… 8 JDK frames elided`.
The 50 MB four-way timing on Slide 5 is **not in this folder** — buffering is the streams unit's subject, so the program lives there: `java ../c2-unit25/FourWays.java` (about a minute; it writes and deletes a 52,428,800-byte file in the current directory).
Every demo creates its scratch directory with `Files.createTempDirectory(Path.of("."), "tiffinbox-…-")`, i.e. **beside this file**, and deletes it before exiting; `Missing.java` writes nothing at all.
