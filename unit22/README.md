# Unit 22 — Sorting and Comparators

- `Sorting.java` — sorting what Java already knows: `names.sort(Comparator.naturalOrder())`, `reverseOrder()`, `Collections.sort(bills)` + `bills.reversed()` (JDK 21+); prints `[Meera, Ravi, Sunil]` / `[Sunil, Ravi, Meera]` / `[3600, 4500, 7200] [7200, 4500, 3600]`. Run: `java Sorting.java`
- `BreakSort.java` — "break it on purpose": `Collections.sort(customers)` on a plain `Customer` does NOT compile (`BreakSort.java:6: error: no suitable method found for sort(ArrayList<BreakSort.Customer>)` … `equality constraints: BreakSort.Customer` / `upper bounds: Comparable<? super T#1>`). `BreakNatural.java` shows the `customers.sort(Comparator.naturalOrder())` form failing the same way (`argument mismatch; inference variable T#2 has incompatible bounds`). Run: `java BreakSort.java` / `java BreakNatural.java` and read the errors.
- `ComparableDemo.java` — fix one: `class Customer implements Comparable<Customer>` with `compareTo` delegating to `name.compareTo(other.name)`; `Collections.sort` now compiles and prints `Meera 1 meals, bill 4500` / `Ravi 2 meals, bill 7200` / `Sunil 1 meals, bill 3600`. (Never name a file `Comparable.java` — it would shadow `java.lang.Comparable` for every sibling snippet.) Run: `java ComparableDemo.java`
- `Comparators.java` — fix two: `Comparator.comparing(Customer::monthlyBill)`, `.reversed()`, `comparing(Customer::getMealsPerDay).thenComparing(Customer::getName)`; prints `Sunil 3600 | Meera 4500 | Ravi 7200 |` / `Ravi 7200 | Meera 4500 | Sunil 3600 |` / `Meera 4500 | Sunil 3600 | Ravi 7200 |`. Run: `java Comparators.java`
- Needs JDK 25 (compact source files + `IO.println`, JEP 512; `reversed()` from SequencedCollection, JDK 21+). Verified on JDK 25.0.4.1.
