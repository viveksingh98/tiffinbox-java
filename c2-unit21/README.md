# c2-unit21 — Money, Overflow and the Bill That Was Wrong (JDK 25.0.4.1, compact source files, no build step)
Setup once: `export JAVA_HOME=/opt/homebrew/opt/openjdk@25; export PATH=$JAVA_HOME/bin:$PATH`. Capture convention for every md5 below (section-wide, see `_briefs/OPEN-FINDINGS.md` #10): `for i in 1 2 3; do <cmd> > NAME.$i.out 2>&1; echo $? > NAME.$i.exit; done; md5 -q NAME.*.out` — the hash covers **combined stdout+stderr only**; the exit code sits beside it and is never folded in.
`java Overflow.java` (exit 1, md5 `63f7dc0b80a5b1b30ecb5838663879da`, 3/3) → the ledger has held **whole rupees in an `int`** since day one; today a ten-paise packaging charge forces `perHoodPaise = perHoodRupees * 100`. Same 884 neighbourhoods, both denominations: `per neighbourhood, rupees : 24300` / `paise : 2430000` / `neighbourhoods that fit, in rupees : 88373` vs `in paise : 883` / `884 hoods as int rupees : 21481200` (positive, 1.0 % of `int` range) / `884 hoods as int paise : -2146847296  = -21,468,472.96 rupees` / `884 hoods as long paise : 2148120000` / `rupee total is negative : false` / `paise total is negative : true`; then `Math.addExact stopped at neighbourhood 884` + `java.lang.ArithmeticException: integer overflow` / `last total it would vouch for: 2145690000 paise = 21,456,900.00 rupees`, and an uncaught `ArithmeticException: integer overflow` at `java.base/java.lang.Math.toIntExact(Math.java:1375)` / `Overflow.main(Overflow.java:45)`. **The `× 100` is the whole bug — nothing in units 01-18 is broken.**
`java Money.java` (exit 0, md5 `f8a0ed7838b25469025aefba1a407bc4`, 3/3) → `0.1 + 0.2 = 0.30000000000000004` / `0.1 + 0.2 == 0.3 : false` / `2.00 - 1.10 = 0.8999999999999999` / `new BigDecimal(0.1) = 0.1000000000000000055511151231257827021181583404541015625` / `double total = 3602.999999999998` (Ravi's 120.10 meal × 30 days) / `BigDecimal total = 3603.00` / `long paise total = 360300  = 3603.00 rupees` / `what the double is short : 2E-12` / `BigDecimal.valueOf(0.1) = 0.1` / `30 ignored adds = 0.00` vs `30 real adds = 3603.00` / `bill 3603.00 scale 2` → `fee 90.07500 scale 5` → `gross 3693.07500 scale 5` → `due 3693.08 scale 2` / `equals(3603.0, 3603.00) : false` but `compareTo == 0 : true` and `in a HashSet : 2 elements`.
`java Rounding.java` (exit 1, md5 `54e50de25825aa429b5787c8a529621d`, 3/3) → `each share, rounded = 33.33` / `three shares add to = 99.99` / `sum.compareTo(bill) = -1` / `missing = 1 paise` / `Math.round(1.005 * 100) / 100.0 = 1.0` but `new BigDecimal("1.005").setScale(2,HALF_UP) = 1.01` (because `1.005` really is `1.00499999999999989341858963598497211933135986328125`) / `Math.round(2.5) = 3  Math.round(-2.5) = -2` vs `HALF_UP 2.5 -> 3  -2.5 -> -3` vs `HALF_EVEN 2.5 -> 2  3.5 -> 4` / then an uncaught `ArithmeticException: Non-terminating decimal expansion; no exact representable decimal result.` at `java.base/java.math.BigDecimal.divide(BigDecimal.java:1810)` / `Rounding.main(Rounding.java:28)`.
