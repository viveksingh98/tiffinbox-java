# c2-unit28 — HttpClient: Calling APIs from Java (JDK 25.0.4.1)
Nothing here touches the public internet. In terminal one: `jwebserver -p 8234 -d "$PWD/www"` (ships with the JDK). In terminal two, no flags: `java ApiCall.java` · `java AsyncCalls.java`; `java Timeout.java` needs no server at all.
`NoImport.java` fails to compile on purpose (`HttpClient` is not in `java.base`); `ApiCall.java` — one `try`-with-resources `HttpClient` (`connectTimeout` 2 s) + one `HttpRequest` (`timeout` 5 s) → `status: 200`, `HTTP_1_1`, `body bytes: 307`, then `week-9.json: 404` to prove `HttpClient` never throws on a status code (6/6 byte-identical, md5 `bc0d5df0…`).
`AsyncCalls.java` — four `sendAsync` calls joined with `CompletableFuture.allOf(...)`, printed by iterating the original list so the output is fixed while the server's arrival order is not; month total `24300` (6/6 byte-identical, md5 `d93d87de…`).
`Timeout.java` — a `ServerSocket` on 8456, **bound to `InetAddress.getLoopbackAddress()`** like every demo server in this course, that accepts and then sleeps a minute; a 500 ms request timeout produces a real `java.net.http.HttpTimeoutException` at `Timeout.java:22` and exit code 1 (6/6 byte-identical, md5 `889a9741…`). Both ports (8234, 8456) were confirmed free with `lsof -nP -iTCP:<port> -sTCP:LISTEN` before and after every capture, and `jwebserver` was killed by PID.
See the HTTP/2 offer the client makes and the server ignores: with `jwebserver` running, `java -Djdk.httpclient.HttpClient.log=frames,headers ApiCall.java` prints the real request headers — `Connection: Upgrade, HTTP2-Settings` / `HTTP2-Settings: AAEAAEAAAAIAAAAAAAMAAAAAAAQBAAAAAAUAAEAAAAYABgAA` / `Upgrade: h2c` — and a response with **no** `Upgrade` header, which is why `response.version()` says `HTTP_1_1`. The request-header block is byte-identical across 3 runs (md5 `fa3fa1d2…`); the JUL timestamps and the `date:` / `last-modified:` response headers change every run.
`BodyHandlers.ofString()` takes **no charset**: it decodes with the response `Content-Type`, falling back to UTF-8. When the server is not yours, write `ofString(StandardCharsets.UTF_8)`.
