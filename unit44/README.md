# Unit 44 — Comments, Javadoc, and How to Read the Java Docs

**What this unit teaches:** the three comment forms, the doc comment as *input to a tool*, `javadoc -d docs` generating a real website with no build tool and no network, the warnings the tool raises when your documentation lies, and how to read the JDK's own pages — starting with `String.substring`.

**You need:** JDK 25 only. Verified on **JDK 25.0.4.1** (`/opt/homebrew/opt/openjdk@25/bin`), `javadoc 25.0.4.1`, `javap 25.0.4.1`. **No network is used or needed** — there is no `-link` flag anywhere here, which is what keeps `javadoc` offline.

Run everything from this folder (`cd unit44`), in the order below.

**Generated `docs/` folders are not committed.** Every command that makes one is below; each is safe to re-run. They are listed in the repo's `.gitignore`.

> **Why two shapes of file in one unit.** Units 03–32 use *compact source files* (`void main()` + `IO.println`, JEP 512) and this unit still does — `Substring.java` and `CatchParent.java` are compact files. But the classes `javadoc` documents (`Customer`, `Order`, `Slip`, `Pause`) are ordinary `public class` files in a package, and `compact/Quick.java` shows exactly why: see the last section.

### javadoc -d brokendocs broken/com/tiffinbox/Order.java — **supposed to warn**

> **This one is supposed to warn — that is the lesson.** `Order.billFor` grew a `customer` parameter and nobody updated the doc comment. Byte-identical over three runs.

### javadoc -d slipdocs broken/com/tiffinbox/Slip.java — **supposed to fail harder**

> A tag that names a parameter which does not exist is not a warning. It is an **error**. Byte-identical over three runs.

```console
$ rm -rf slipdocs && javadoc -d slipdocs broken/com/tiffinbox/Slip.java
...
broken/com/tiffinbox/Slip.java:11: error: @param name not found
     * @param dayz days delivered
              ^
broken/com/tiffinbox/Slip.java:14: warning: no @param for days
    public static int billFor(int days) { return days * 120; }
                      ^
...

```

A missing tag is a **warning**; a tag pointing at nothing is an **error**. The tool is a second compiler for your documentation.

### java Substring.java — **supposed to fail**

> **This one is supposed to fail — that is the lesson.** The JDK's own `@throws` clause for `String.substring(int, int)` promises this exact exception, and here it is. Byte-identical over three runs.

```console
$ java Substring.java
substring(8, 14) -> cheese
Exception in thread "main" java.lang.StringIndexOutOfBoundsException: Range [14, 8) out of bounds for length 20
	at java.base/jdk.internal.util.Preconditions$1.apply(Preconditions.java:55)
	at java.base/jdk.internal.util.Preconditions$1.apply(Preconditions.java:52)
	at java.base/jdk.internal.util.Preconditions$4.apply(Preconditions.java:213)
	at java.base/jdk.internal.util.Preconditions$4.apply(Preconditions.java:210)
	at java.base/jdk.internal.util.Preconditions.outOfBounds(Preconditions.java:98)
	at java.base/jdk.internal.util.Preconditions.outOfBoundsCheckFromToIndex(Preconditions.java:112)
	at java.base/jdk.internal.util.Preconditions.checkFromToIndex(Preconditions.java:349)
	at java.base/java.lang.String.checkBoundsBeginEnd(String.java:4937)
	at java.base/java.lang.String.substring(String.java:2899)
	at Substring.main(Substring.java:4)
```

Exit code: `1`. Ten `at` lines: eight JDK frames, then `String.substring`, then your file on the last line.

**Where the documentation comes from.** The JDK ships its own source in a file called `src.zip`, inside the
JDK's own folder. Inside `src.zip`, `java.base/java/lang/String.java` carries the doc comment for
`substring(int, int)` starting at **line 2875**.

**Finding that folder.** Do **not** assume `$JAVA_HOME` is set — on a clean Mac login shell it is usually
empty, and `$JAVA_HOME/lib/src.zip` then expands to `/lib/src.zip`, which does not exist. `/usr/libexec/java_home`
is not reliable either: it only knows about JDKs installed under `/Library/Java/JavaVirtualMachines`, so on a
Homebrew machine `/usr/libexec/java_home -v 25` can answer with a completely different JDK (it answered with
**23.0.1** on the machine these captures were taken on). Ask the JVM you are actually running instead — this
works on macOS, Linux and Windows, whatever installed it:

```console
$ java -XshowSettings:properties -version 2>&1 | grep 'java.home'
    java.home = /opt/homebrew/Cellar/openjdk@25/25.0.4.1/libexec/openjdk.jdk/Contents/Home
```

Then set `JAVA_HOME` from that, and `src.zip` is one `lib/` below it:

```console
$ JAVA_HOME=$(java -XshowSettings:properties -version 2>&1 | awk -F'= ' '/java\.home/{print $2}')
$ ls -l "$JAVA_HOME/lib/src.zip"
-rw-r--r--  1 you  admin  53646209 ... /opt/homebrew/Cellar/openjdk@25/.../lib/src.zip
```

(The Homebrew keg in the Director's Note, `/opt/homebrew/opt/openjdk@25`, has no `lib/` of its own — only
`bin`, `include` and `libexec`. The real JDK home is
`/opt/homebrew/opt/openjdk@25/libexec/openjdk.jdk/Contents/Home`, which is what the command above prints.)

The doc comment itself:

```java
/**
 * Returns a string that is a substring of this string. The
 * substring begins at the specified {@code beginIndex} and
 * extends to the character at index {@code endIndex - 1}.
 * Thus the length of the substring is {@code endIndex-beginIndex}.
 * <p>
 * Examples:
 * <blockquote><pre>
 * "hamburger".substring(4, 8) returns "urge"
 * "smiles".substring(1, 5) returns "mile"
 * </pre></blockquote>
 *
 * @param      beginIndex   the beginning index, inclusive.
 * @param      endIndex     the ending index, exclusive.
 * @return     the specified substring.
 * @throws     IndexOutOfBoundsException  if the
 *             {@code beginIndex} is negative, or
 *             {@code endIndex} is larger than the length of
 *             this {@code String} object, or
 *             {@code beginIndex} is larger than
 *             {@code endIndex}.
 */
public String substring(int beginIndex, int endIndex) {   // line 2897
    int length = length();                                // line 2898
    checkBoundsBeginEnd(beginIndex, endIndex, length);     // line 2899
```

`String.java:2899` in the trace above is that `checkBoundsBeginEnd` line — three lines below the comment you just read. To see this yourself without unzipping anything, put the cursor on `substring` in IntelliJ and press **⌘B** (macOS) / **Ctrl+B** (Windows).

Unzip it yourself if you want to (it is a large tree — do it in a scratch folder, not in this repo):

```console
$ JAVA_HOME=$(java -XshowSettings:properties -version 2>&1 | awk -F'= ' '/java\.home/{print $2}')
$ unzip -q "$JAVA_HOME/lib/src.zip" 'java.base/java/lang/String.java' -d /tmp/jdksrc
$ sed -n '2875,2899p' /tmp/jdksrc/java.base/java/lang/String.java
```

### cd deprecated && java SameFile.java

> The honest footnote: the warning appears only when the **caller is in a different file**. Put the same deprecated method and the same call in one *compilation unit* — the JLS's name for **one source file and everything in it** — and the compiler says nothing at all. ### cd compact && java Quick.java — why the documented classes are not compact files

> A compact source file **can** hold a `public class` (this one does, and it runs). What it cannot do is produce documentation in the right shape.

```console
$ cd compact
$ java Quick.java
3600
$ rm -rf docs && javadoc -d docs Quick.java
...
Generating docs/Quick.html...
Generating docs/Quick.Billing.html...
Generating docs/package-summary.html...
...
```

Zero warnings — and still wrong for a real project, for two measured reasons:

```console
$ javac -d out Quick.java && javap -p -cp out 'Quick$Billing'
public class Quick$Billing {
  private Quick$Billing(Quick);
  public static int bill(int);
}
$ grep -o '<title>[^<]*</title>' docs/package-summary.html
<title>Unnamed Package</title>
```

1. `Billing` became **`Quick$Billing`** — a *member* of the file's implicit class, which is why its page is `Quick.Billing.html` and not `Billing.html`.
2. Everything landed in the **Unnamed Package**. Every page in the JDK's documentation lives in a package.

That is why `Customer`, `Order`, `Slip` and the exercise's `Pause` are ordinary `public class` files under `src/main/java/com/tiffinbox/` — Unit 33's layout, which is what `javadoc` is built for.
