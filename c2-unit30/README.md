# c2-unit30 — A Tiny HTTP Server: jdk.httpserver on Virtual Threads (JDK 25.0.4.1)
Everything below binds **127.0.0.1 only** on port **8345**, and **one demo owns that port at a time**. Check it is free first — `lsof -nP -iTCP:8345 -sTCP:LISTEN` — and stop every server you start. At **runtime** nothing here touches the network beyond your own machine; the **build** downloads `jackson-databind:2.22.2` and its two transitive jars from Maven Central the first time, after which `mvn -o` works offline.

**1. The server** (Maven, one dependency: `jackson-databind:2.22.2`): `mvn -q compile exec:java` → prints `TiffinBox answering HTTP on 8345`, then one line per request: `  GET /customers         -> 200  virtual=true  VirtualThread[#44]/runnable@ForkJoinPool-1-worker-1` (the `#44` and the `worker-1` differ every run; `virtual=true` never does). Stop it with `Ctrl-C`. In another terminal: `curl -s http://localhost:8345/customers` · `curl -i http://localhost:8345/customers/ravi` (→ `Content-length: 61`) · `curl -i http://localhost:8345/customers/nobody` (→ `404 Not Found` and a **JSON** body, 44 bytes). Ignore the `Date:` header — it is the only line that changes between runs. `Customer` carries `@JsonProperty("veg")`, exactly as the Jackson unit's record does, so the key on the wire is `veg` and the single-customer body is the same **61** bytes that unit prints.

**2. The failure** — `java BindTwice.java` (compact source file, no dependencies, exit code 0, 6/6 runs byte-identical, md5 `81bb9cd8…`): binds 8345, then binds it again and prints the real `java.net.BindException: Address already in use`. Delete its `finally { first.stop(0); }` and the JVM **never exits** — measured here at over 20 seconds before a `kill -9`.

**3. Shutting down properly** — `java Shutdown.java` (3/3 byte-identical, md5 `58dff347…`): `System.exit(0)` inside a `try` whose `finally` **never runs**, and a `Runtime.addShutdownHook` that does, calling `stop(2)` so in-flight exchanges get up to two seconds to finish. `kill -9` still runs nothing.

**4. Order ids** — `java OrderIds.java`: `new Random(42)` built twice prints the **same** id `ORD-359D41BAF78A` both times (and on your machine too — `java.util.Random`'s algorithm is specified in its javadoc); `SecureRandom` prints a different id every single time. Never generate an order id, a session id or a token with `java.util.Random`.

**5. Why `setExecutor` matters** — `java NoExecutor.java` starts the same server with **no executor set**. `curl localhost:8345/plain` prints `Thread[#26,HTTP-Dispatcher,5,main]` / `isVirtual(): false`: one thread for the whole server. Then fire two at once — `curl -s localhost:8345/slow & curl -s localhost:8345/slow &` — and the log reads `enter #1` / `exit #1` / `enter #2` / `exit #2`: **request two does not start until request one finishes** (3/3 byte-identical, md5 `f1bf8ff1…`). It also serves `/zero` (`sendResponseHeaders(200, 0)` → `Transfer-encoding: chunked`) and `/none` (`sendResponseHeaders(204, -1)` → no body at all). It has no keep-alive trick: `HttpServer`'s dispatcher thread is not a daemon and holds the JVM open by itself. Kill it with `Ctrl-C` when you are done.
