# c2-unit24 — Class Loading: How a .class Becomes a Class (JDK 25.0.4.1, no build tool)
Setup, once: `export JAVA_HOME=/opt/homebrew/opt/openjdk@25; export PATH=$JAVA_HOME/bin:$PATH`, then `javac -d out Kitchen.java Diner.java Menu.java Lazy.java Loaders.java Lookup.java`. **The hook:** `java -cp out Diner` prints `1. diner opened` / `2. Meera served`; now `rm out/Kitchen.class` and run the *same* command — `1. diner opened` still prints, then `NoClassDefFoundError: Kitchen` / `at Diner.main(Diner.java:4)` / `Caused by: ClassNotFoundException: Kitchen` / `… 1 more`, exit `1` (3/3 runs byte-identical, md5 `f92250de…`). Everything below assumes `out/Kitchen.class` stays deleted.
**The chain:** `java -cp out Loaders` → `app` → `platform` → `null` (the bootstrap loader is C++ inside the JVM), `java.sql.Driver` on `platform`, `javax.xml.parsers.DocumentBuilder` on **bootstrap**, and `Loaders' module : null` (3/3 byte-identical, md5 `e70ee9d3…`). **The security boundary, proved:** `javac -d fake fakesrc/java/lang/String.java` is refused (`package exists in another module: java.base`), so use `javac --patch-module java.base=fakesrc -d fake fakesrc/java/lang/String.java`; then `java -cp fake:out Loaders | md5` equals `java -cp out Loaders | md5` — **the same md5, `e70ee9d3…`** — and the fake's `static` block never prints.
**Lazy loading:** `java -cp out Lazy` prints `2. Menu.MAX_MEALS = 3` with **no** static block, then wakes `Menu` at print 4 (md5 `42ad858c…`). Why: `javap -c -p out/Lazy.class` shows `11: ldc #23 // String 2. Menu.MAX_MEALS = 3` (constant folded, `Menu` not named) versus `27: getstatic #27 // Field Menu.TODAY:Ljava/lang/String;`. Watch the JVM say it: `java -Xlog:class+load=info:stdout:none -cp out Lazy | grep -E '^[0-9]\. |^   >>>|source: file:'` — byte-identical on 6 runs (md5 `f8599d5e…`); `-verbose:class` is **unusable** (uptime stamps, 3 runs → 3 md5s). Class count: `… | grep -c ' source: '` → **606** from a path with no space in it, **609** from one that has a space (the URL decoder loads too).
**The three errors:** `javac -d out Lookup.java; java -cp out Lookup` → `ClassNotFoundException : Kitchen` and `the program carries on` (checked, recoverable; md5 `0715a4ee…`). `javac -d o2 Config.java Boot.java; java -cp o2 Boot` touches `Config` twice → `attempt 1 -> java.lang.ExceptionInInitializerError` (caused by `NumberFormatException: For input string: "not-a-number"`) then `attempt 2 -> java.lang.NoClassDefFoundError: Could not initialize class Config` (md5 `7847ef3f…`); `java -Dtiffinbox.limit=3 -cp o2 Boot` prints `limit 3` twice (md5 `9b178b3a…`).
**Your own loader:** `mkdir -p app plugins; javac -d app Special.java Plugins.java; javac -cp app -d plugins SeasonalMenu.java; java -cp app Plugins plugins` → `on the class path? false` / `[plugin-1] read 336 bytes, magic = 0xCAFEBABE` / `Garden Bowl, Grilled Wrap, Soup of the Day` / `delegation check : String loaded by null` / `same name : true` / `same Class object : false` / `cast across loaders: ClassCastException: Cannot cast SeasonalMenu to SeasonalMenu` (3/3 byte-identical, md5 `72bed250…`). `SeasonalMenu` is compiled **only** into `plugins/`; `Plugins.java` reaches it through `Class.forName`, a string, so it never lands on the app classpath. Re-measure `336` if you edit `SeasonalMenu.java`.
**The second guard, proved (added 2026-09-14 on RED's M2):** delegation is only the *first* guard, and the deck used to say it was the whole story. `NoDelegate.java` is the loader Slide 5 warns about — `loadClass` overridden, own folder searched first, parent never asked — pointed at the same `fake/` tree: `javac -d nd NoDelegate.java; java -cp nd NoDelegate` → `  [rogue] found java.lang.String locally — parent not asked` then `Exception in thread "main" java.lang.SecurityException: Prohibited package name: java.lang` at `java.base/java.lang.ClassLoader.preDefineClass(ClassLoader.java:847)` / `defineClass(ClassLoader.java:960)` / `defineClass(ClassLoader.java:826)` / `NoDelegate$Rogue.loadClass(NoDelegate.java:19)` / `NoDelegate.main(NoDelegate.java:28)` — exit 1, 3/3 byte-identical, md5 `c4dedce78d50ac0a08a17dcb298a6434`. **`defineClass` refuses any name beginning `java.` outright**, so the fake `String` still does not load. Overriding `loadClass` lets you shadow *your own* classes by accident, not the JDK's.
**Honest limit on the `-Xlog:class+load` md5:** it is **path-dependent** — the filtered lines contain the absolute `source: file:/…` of your `out/` folder. `f8599d5e…` is from the shipped tree, `8f89ef90…` from a scratch copy; both 3/3 byte-identical *within* their directory. Same cause as the 606 vs 609 class count. The slide now says so.
