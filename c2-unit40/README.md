# c2-unit40 — Annotations: Define, Read and Process Them (JDK 25.0.4.1)
Six top-level source files; compile and run them together, no flags: `javac -d out *.java` then `java -cp out MiniFramework`.
`Route.java` / `Range.java` / `NotBlank.java` are the annotations (`@Retention(RUNTIME)` + `@Target(METHOD)` / `@Target(RECORD_COMPONENT)`); `Handlers.java` has three `@Route` methods plus `notARoute()` as a control, and `Customer.java` is the record wearing `@NotBlank` / `@Range`; `MiniFramework.java` scans, validates and dispatches in about sixty lines and prints `routes: 3 of 4 methods` and `GET /revenue  ->  24300` — byte-identical on 6/6 runs, md5 `765d8348…`.
Break it on purpose — `break1/` replaces `Route.java` with `@Retention(RetentionPolicy.CLASS)` (same commands → `routes: 0 of 4 methods`, every call `404 no handler`, and the annotation prints as `null`); `break1-naive/` is that same change plus a `dispatch` without the null check (→ `NullPointerException` at `MiniFramework.java:48`).
`break2/` replaces `Handlers.java` with `@Route` on a field: `javac -d out *.java` fails with `error: annotation interface not applicable to this kind of declaration` — that is `@Target(ElementType.METHOD)` doing its job at compile time.
Copy a break folder's files over the top-level ones (or compile inside it with the unchanged files copied in) to reproduce; the top-level sources are always the working version.
