# Unit 31 — Pattern Matching: instanceof and switch

- `Patterns.java` — Unit 18's `Order` / `MealType` / sealed `Payment` family plus `record Receipt(Order order, Payment payment)`; `instanceof Order order && …`, `describe(...)` with record patterns and a `when` guard, `summarise(...)` three patterns deep; prints `Ravi ordered 2 meals` / `cash at the door` / `UPI to ravi@okbank` / `Visa ending 4421` / `card ending 5123` / `Meera paid for 1 NON_VEG by UPI (meera@okbank)` / `Sunil paid 130 another way`. Run: `java Patterns.java`
- `OrScope.java` — `instanceof Order order || order.quantity() > 1` does NOT compile (`OrScope.java:3: error: cannot find symbol` · `symbol: variable order`): after `||` the test may have failed. Run: `java OrScope.java` and read the error.
- `NullSwitch.java` — `describe(null)` throws `java.lang.NullPointerException` from inside the `switch` (`at NullSwitch.describe(NullSwitch.java:7)`); fix: `case null -> "no payment yet";` as the first case. Run: `java NullSwitch.java`
- `BreakGuard.java` — only the guarded `case Card(...) when` remains, so it does NOT compile (`BreakGuard.java:6: error: the switch expression does not cover all possible input values`); `BreakDominated.java` — plain `case Card` before the `when` case does NOT compile (`BreakDominated.java:10: error: this case label is dominated by a preceding case label`). Run each and read the error.
- Needs JDK 25 (compact source files + `IO.println`, JEP 512; pattern matching for `instanceof` JEP 394, for `switch` JEP 441, record patterns JEP 440). Verified on JDK 25.0.4.1.
