# c2-unit34 — SQL in 15 Minutes: TiffinBox Tables in H2 (JDK 25.0.4.1, Maven 3.9.16)
1. `export JAVA_HOME=/opt/homebrew/opt/openjdk@25; export PATH=$JAVA_HOME/bin:$PATH` — on this Mac a bare `mvn` picks Java 26 and a bare `java` picks Java 23; pin the JDK or you are not running what was verified.
2. `mvn -q compile exec:java -Dexec.mainClass=Sql101` — no database to install: `com.h2database:h2:2.5.250` **is** the database and `jdbc:h2:./data/tiffinbox` creates `data/tiffinbox.mv.db` (20,480 bytes after a clean first run, measured twice; it grows 4-8 KB on every re-run because MVStore appends — delete `data/` to start clean).
`Db.java` — the one `Db` the whole section shares: `URL` / `USER` / `PASS`, `open()`, `reset(Connection)`, `countOrders(Connection)`. `DROP ALL OBJECTS`, then `customers` (`PRIMARY KEY`, `NOT NULL`, named `uq_customer_email UNIQUE`) and `orders` (`AUTO_INCREMENT`, named `fk_order_customer FOREIGN KEY`), plus 4 customers / 6 orders.
`Sql101.java` — `SELECT` · `WHERE` · `JOIN` · `GROUP BY`; then `RETURN_GENERATED_KEYS` + `getGeneratedKeys()` (`new order id: 7`); then two deliberate failures — `SELECT nmae` → `42S22` / code `42122`, and a duplicate email → `23505` naming `PUBLIC.UQ_CUSTOMER_EMAIL`, with `customers still: 4`.
Output is byte-identical on every run (3/3, md5 `41dba9a8219551258e7cec89d5326650`) because `reset()` rebuilds the schema and every `SELECT` carries an explicit `ORDER BY`; alias `AS order_value`, never `AS value` (`VALUE` is reserved).
