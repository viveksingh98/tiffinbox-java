# c3-unit06 — Settings, the Repository, and Why Maven 4 Is Still Not Here (Maven 3.9.16, JDK 25.0.4.1)
**Line 1 of every command below**, or Maven picks up Java 26.0.2.1 and a bare `java` is 23.0.1: `export JAVA_HOME=/opt/homebrew/opt/openjdk@25; export PATH="$JAVA_HOME/bin:$PATH"`. Then, from this folder, `M2="$PWD/.m2-unit06"` — **keep the quotes**, this path contains a space, and unquoted in bash the same line dies with `[ERROR] Unknown lifecycle phase "Content/LearnProgrammingWithVivek/…"` (zsh 5.9 does not split, so it survives there; quote it and stop caring). Every `mvn` below carries `-Dmaven.repo.local` and touches only `$M2` (or `/tmp/m2consumer` in step 3), never your real `~/.m2` — with one deliberate exception: step 1's `help:effective-settings` has to resolve against the real repository in order to print it, so that one command does download `maven-help-plugin` into `~/.m2`.
1. **Settings you never wrote:** `ls ~/.m2/settings.xml` → `No such file or directory`, then `mvn -B -q help:effective-settings -Doutput=es.xml; sed -n '13,28p' es.xml` → `<localRepository>…/.m2/repository</localRepository>`, `<interactiveMode>false</interactiveMode>`, a mirror `maven-default-http-blocker` sending `external:http:*` to `http://0.0.0.0/` with `<blocked>true</blocked>`, and `<pluginGroups>` holding `org.apache.maven.plugins` + `org.codehaus.mojo`. 3/3 byte-identical, md5 `1d2b9ecc9b088ac1dba7a707d82e1b42` over those 16 lines (the file's header comment names your user and host — that part is machine-local).
2. **`install` vs `deploy`:** `rm -rf "$M2"/com/tiffinbox; mvn -B "-Dmaven.repo.local=$M2" clean install` prints 5 `Installing` lines and leaves **11 files** under `"$M2"/com/tiffinbox` — jars, poms, `_remote.repositories`, `maven-metadata-local.xml`, **no checksums**. Then `mvn -B "-Dmaven.repo.local=$M2" clean deploy` writes `file://${maven.multiModuleProjectDirectory}/target/team-repo` (see `<distributionManagement>` in `pom.xml`): 8 `Uploaded to tiffinbox-team:` lines and **24 files**, every one with a `.md5` and a `.sha1` beside it plus a real `maven-metadata.xml` carrying `<release>1.0.0</release>`. Verify a checksum by hand: `shasum target/team-repo/com/tiffinbox/tiffinbox-core/1.0.0/tiffinbox-core-1.0.0.jar` matches that file's `.sha1` (`1408ec152a3e3f418d725f504fbe43f6ea2d913a`).
3. **The mirror and the team repository, proved by repository id:** `export TEAM_REPO="$PWD/target/team-repo"; cd consumer; rm -rf /tmp/m2consumer; mvn -B -s ../settings.xml "-Dmaven.repo.local=/tmp/m2consumer" clean package` → on a **cold** consumer repository, **174** `Downloading from central-mirror:` lines and **3** `Downloading from tiffinbox-team: file:///…` (3/3 runs, identical counts; a warm repository downloads nothing). `central-mirror` and `tiffinbox-team` are ids from `settings.xml`; no POM here names either. The proof it really came from there is the file `/tmp/m2consumer/com/tiffinbox/tiffinbox-core/1.0.0/_remote.repositories`, which reads `tiffinbox-core-1.0.0.jar>tiffinbox-team=`.
4. **Reproducible builds, byte-compared:** `for i in 1 2 3 4 5 6; do mvn -B -q "-Dmaven.repo.local=$M2" "-Dproject.build.outputTimestamp=" clean package; md5 -q tiffinbox-core/target/*.jar; done` → **six different hashes, every jar 3426 bytes**, and each pair of them differs **only inside modification-time fields — zero bytes anywhere else** (checked with a zip-structure parser on all 15 pairs). The *count* depends on the clock: `cmp -l a.jar b.jar | wc -l` is **22** when the builds are seconds apart and **44** across an 8-minute boundary — 11 of the jar's 12 entries × the two places a zip stores each entry's clock × however many of the DOS time field's two bytes moved (the low byte carries seconds and minute-mod-8, so only it moves inside one 8-minute block). Measured both ways on this Mac: 22 at 13:50:15→13:51:03, 44 at 00:03:52→00:08:13. Drop `-Dproject.build.outputTimestamp=` so the parent's `<project.build.outputTimestamp>2026-09-14T00:00:00Z</project.build.outputTimestamp>` applies and the same loop prints `03a523276277fa6efd292152936a41d9` **6/6** (web jar `4e40f21e53f95108408bc7f173c1ea69`), `unzip -l` stamps every entry `00:00`, and a copy of this tree built at a different absolute path gives the same hash with `cmp` silent. `mvn -B "-Dmaven.repo.local=$M2" org.apache.maven.plugins:maven-artifact-plugin:3.6.0:check-buildplan` → `No known issue in 2 plugins` / `in 6 plugins` / `in 6 plugins`, 3/3.
5. **Run it, and the exercise:** `java -cp "tiffinbox-web/target/tiffinbox-web-1.0.0.jar:tiffinbox-core/target/tiffinbox-core-1.0.0.jar" com.tiffinbox.web.Dashboard` → `Meera -> 3600` / `Ravi -> 5400` / `Priya -> 2250` (3/3, md5 `763da9925197453b5e61f11003d941f3`); without the `JAVA_HOME` export it is `UnsupportedClassVersionError: … class file version 69.0, this version of the Java Runtime only recognizes class file versions up to 67.0`. In `exercise/`, `for i in 1 2 3; do mvn -B -q "-Dmaven.repo.local=$M2" clean package; md5 -q tiffinbox-kitchen/target/*.jar; done` prints three different hashes — add one line to `exercise/pom.xml`'s `<properties>` and it prints `ec6afdd1d1188b7b00adb4465895827d` three times; the answer is `exercise/solution/pom.xml`. Offline receipt: `mvn -o -B "-Dmaven.repo.local=$M2" verify` → `BUILD SUCCESS` for the reactor, `consumer/` and `exercise/`.
